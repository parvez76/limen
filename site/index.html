Parvez

The usual security mistakes don't compile.

A small language for backend services and DevOps tools. You write a few lines. The compiler refuses the route nobody guarded, the secret headed for a log, and the query pasted together from strings. What you get back is one native binary.

Install

Linux (x86_64, ARM64) and macOS (Apple silicon):

curl -fsSL https://parvez76.github.io/project-parvez/install.sh | sh

The installer checks the download against the release's SHA256SUMS (and its signed build attestation when the gh CLI is installed), puts parvez in ~/.parvez/bin, and offers to set up the Rust toolchain if it's missing. Read it first: install.sh.

Start

parvez doctor              # check the setup
parvez new hello && cd hello
parvez test main.prvz      # tests
parvez run main.prvz       # http://localhost:8080

Later, parvez upgrade moves to the newest release, verified the same way.

What it feels like

  • Friday deploys get boring. Every endpoint says who may call it, or the build stops. Injectable SQL, and file paths and commands built from request input, are compile errors with the fix, even after the input passed through helpers, traits or stored state.
  • The whole service fits on one screen. A JSON service is 9 lines, where the hand-written Rust is 48 (see both).
  • When your agent slips, it lands on the right line. The spec is one file written for AI agents, and errors point at your .prvz line.
  • Leaving costs nothing. It compiles to plain, readable Rust; parvez show hands it over.

What it won't do

It won't catch your logic mistakes: if a guard returns the wrong answer, Parvez enforces the wrong answer. It runs on top of Rust, covers Linux and Apple-silicon Macs, and is pre-1.0. The full list.
